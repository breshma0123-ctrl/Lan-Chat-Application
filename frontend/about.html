🌐 Computer Networks in this Project

This project implements a decentralized multi-client real-time messaging application over a Local Area Network (LAN) without requiring external internet or third-party cloud services. Below are the core networking fundamentals implemented in the code.

LAN
Local Area Network
A network covering a small geographical area, such as a home, college lab, or office Wi-Fi. Devices communicate directly via local IP addresses (e.g. 192.168.x.x) switched by the Wi-Fi router.
Router: 192.168.1.1 ➔ Allocates local IPs to Laptop A, B, and Server
Layer 3
IP Address (0.0.0.0 vs 127.0.0.1)
An Internet Protocol address identifies a device on a network. 127.0.0.1 (localhost) only accepts connections from the same PC. Binding the server to 0.0.0.0 instructs the OS to listen on all network adapters, allowing other LAN devices to connect.
socketio.run(app, host='0.0.0.0', port=5000)
Layer 4
Port Number (:5000)
While the IP address directs traffic to the host computer, the Port Number directs incoming packets to the exact application process. Our Flask server listens on port 5000.
http://192.168.1.10:5000 ➔ Port 5000 routes packets to Python
Arch
Client-Server Architecture
A centralized model where the Server acts as the central hub managing user state, rooms, authentication, and database persistence, while Clients (browsers on PCs/phones) render the UI and exchange events.
Client A ➔ WebSocket ➔ Flask Server ➔ Client B
Transport
TCP (Transmission Control Protocol)
Underlying both HTTP and WebSockets is TCP. TCP guarantees ordered, reliable, connection-oriented packet delivery using 3-way handshakes (SYN, SYN-ACK, ACK) and retransmissions.
TCP 3-Way Handshake ➔ Reliable Byte Stream ➔ Zero Packet Loss
Protocol
WebSocket vs. HTTP Polling
HTTP is unidirectional (client requests, server responds, connection closes). WebSocket establishes a persistent, full-duplex TCP channel over a single socket, allowing the server to push new messages to clients instantly without polling.
HTTP Upgrade Handshake ➔ Persistent Full-Duplex Stream
Routing
Socket Rooms & Private Messaging
Flask-SocketIO provides logical Rooms. Every user automatically joins room general (for broadcasts) and a private room named after their username for direct 1-to-1 secure message delivery.
emit('private_message', data, room=receiver_username)
Systems
Multi-Client Concurrency
async_mode="threading"
The server handles multiple concurrent network connections simultaneously using background threads, isolating client socket reads and writes.

📊 End-to-End Packet Lifecycle

1. Client 1 types a message and clicks [SEND] 2. Browser JavaScript triggers: socket.emit('send_message', payload) 3. WebSocket frame encapsulated into TCP segment (Port 5000) 4. Wi-Fi Router routes IP packet to Server Computer (e.g. 192.168.1.10) 5. Flask-SocketIO processes payload, saves to SQLite (chat.db) 6. Server broadcasts event: emit('receive_message', data, room='general') 7. Client 2 receives WebSocket frame over active TCP connection 8. Browser DOM dynamically appends message bubble without page reload!
